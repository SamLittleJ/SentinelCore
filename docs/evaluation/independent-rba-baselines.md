# Baselines and thresholds on the RBA login data set

Generated by `make evaluate-rba-offline` (commit `28d91ad4113a-dirty`) in 10 minutes, on the sample of `independent-rba.md`. The rules are replayed in Python (`backend/simulator/rba_offline.py`): at the application's thresholds the replay reproduced every number of the API run in `independent-rba.json`, or this file would not have been written. Every other threshold below is a sensitivity analysis on the evaluation data; no setting was changed because of it. Data: *Login Data Set for Risk-Based Authentication*, Wiefling et al., 2022, [DOI 10.5281/zenodo.6782155](https://doi.org/10.5281/zenodo.6782155), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

## B2: the Freeman et al. risk score against the T1078 rule

Each successful sign-in of the sampled users, labelled by the takeover flag. B2 scores each one; flagging every score above a threshold trades takeovers detected against false alarms, the share of the other sign-ins flagged. The rule is one such trade. *With history* keeps the sign-ins that came after at least 3 successful ones in 90 days, the only ones the rule judges: the main comparison. B2 is the interpolated score with 90 days of history (Method, below).

What drives the main score: the median of each of its terms, in log10, over the sign-ins with history. A term higher for the takeovers pushes them up the ranking.

| Term | Takeovers | Others |
| --- | --- | --- |
| p(u | attack) | -6.28 | -6.35 |
| 1 / p(u | legit) | 5.78 | 5.75 |
| p(address) | -6.77 | -5.89 |
| 1 / p(address | u, legit) | 1.07 | 0.70 |
| p(user agent) | -4.02 | -3.06 |
| 1 / p(user agent | u, legit) | 1.02 | 0.87 |

Freeman's model takes an attacker's address and user agent to be drawn like everyone's: p(x | attack) is estimated by p(x), the value's share of all sign-ins. Where the takeovers come from values rarer in the whole data than the other sign-ins' values, p(x) lowers their score more than their novelty to the user, 1 / p(x | u, legit), raises it. Freeman et al. correct p(x) with a reputation of each value, p(A | x), which this data set does not provide; using its attacker label in its place would fit the baseline to the labels it is judged by.

## Method

- **B2.** Freeman et al., *Who Are You? A Statistical Approach to Measuring User Authenticity*, NDSS 2016, as Wiefling et al. used it on this data's source (*Pump Up Password Security!*, ACM TOPS 2023, DOI 10.1145/3546069): Wiefling's Eq. 1, Freeman's Eq. 7 without the reputation term. Features: the address, with its ASN and country; the user agent, with its browser, OS and device type. Each level is Freeman's Eq. 9 with Eq. 8 smoothing (M the distinct values seen in the group), combined by Eq. 11 with Wiefling's weights (address 0.6, ASN 0.3, country 0.1; user agent 0.53, browser 0.27, OS 0.19, device type 0.01), which come from an earlier study. Reading those weights as Eq. 11's coefficients is ours: Wiefling gives the weights, not the formula. No weights were learned (Freeman's Eq. 13): that would fit the labels.
- **B2's state.** p(x) and p(u | legit) count every successful sign-in of the whole data before the one scored, in time order, as Wiefling replayed it. A user's history is their successful sign-ins of the last 90 days (Freeman used six months: the 180-day variant), from the window's start only, as the API run saw. A user with none gets the highest score: neither paper scores one, so that choice is ours.
- **The rule as a point.** Its alerts at the application's thresholds, on the same sign-ins and labels as B2; false alarms are a share of the successful non-takeover sign-ins, not per 1,000 of all sign-ins as in `independent-rba.md`.
- **Intervals.** 95% Wilson score intervals.
