## Method

- **Window.** The last 360 days of the data (2020-03-05 to 2021-02-28): ingestion refuses events more than a year old.
- **Sample (A).** Every user with a confirmed takeover in the window, and ordinary users drawn from each group by number of sign-ins (1-9, 10-49, 50+) in proportion to the data's: 1-9: 3744013, 10-49: 313252, 50+: 10546 users. The sampled users become accounts of one organization.
- **Weeks (B).** Whole weeks drawn at random in the window, not overlapping, every sign-in included, each in its own organization, with no accounts: the spray rule needs only the emails.
- **Replay.** Each experiment's times are moved together so that it ends an hour before the run, keeping their order and spacing; sign-ins go through the ingestion API in batches, oldest first, with the server's ingestion rate limit raised for the run. Sign-ins with an invalid address were skipped (A: 0; weeks: 0, 0, 0).
- **Thresholds.** The application's settings, never fitted to this data: `detection_spray_min_accounts` 10, `detection_spray_window_minutes` 15, `detection_unfamiliar_lookback_days` 90, `detection_unfamiliar_min_sign_ins` 3, `detection_dormant_days` 90, `login_max_failed_attempts` 5, `login_failure_window_minutes` 15, `login_lockout_minutes` 15.
- **Intervals.** 95% Wilson score intervals.
- **What the synthesis changes.** The data set's addresses were generated anew for each distinct real one, so two addresses of one real network rarely share a /24 here. The T1078 rule treats a /24 as a familiar network; on this data it mostly recognises exact addresses only, which raises its false alarms. Its times contain randomness too, which may spread out bursts.
- **Not measured here.** Brute force (it watches only this application's own sign-ins), password spray across organizations (the data has one service) and privileged roles (no such events): see the simulator's report, `report.md`. Time to detect is measured there too: these times are partly random.
